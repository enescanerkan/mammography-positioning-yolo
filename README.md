# Mammography Breast Positioning Quality Assessment via YOLO Pose Estimation

Automated evaluation of mammographic breast positioning quality using YOLO keypoint detection.
A pose estimation model detects three anatomical landmarks on MLO images (nipple, pectoral top,
pectoral bottom) and one on CC images (nipple).  The predicted landmark positions are used to
compute the Posterior Nipple Line (PNL) and the chest-wall distance, which are compared via the
clinical **10 mm rule** to classify positioning quality as *Good* or *Bad*.

## Clinical Background

Mammographic positioning quality is assessed by measuring the
**Posterior Nipple Line (PNL)** on the MLO view and comparing it with
the nipple-to-chest-wall distance on the CC view.

> If |PNL_MLO − Distance_CC| ≤ 10 mm → **Good** positioning, otherwise **Bad**.

### Keypoints

| View | Keypoints detected | Count |
|------|--------------------|-------|
| MLO (Mediolateral Oblique) | `nipple`, `pectoral_top`, `pectoral_bottom` | 3 |
| CC (Craniocaudal) | `nipple` | 1 |

## Quick Start

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

### 2. Add raw DICOMs

Place the VinDr-Mammo DICOM files under `data/raw/`:

```
data/raw/<study_uid>/<sop_uid>.dicom
```

### 3. Annotation labels

The expert annotations are included in this repository — no extra download needed:

```
data/labels/mlo_labels.csv
data/labels/cc_labels.csv
```

See [`data/labels/README.md`](data/labels/README.md) for the annotation protocol,
the CSV schema, and the train/val/test split.

### 4. Run an end-to-end experiment

```bash
# Preprocess (Wavelet strategy) + flip augmentation + train — MLO view
python main.py --config configs/wavelet_mlo.yaml --mode full --augment

# Same for CC view
python main.py --config configs/wavelet_cc.yaml --mode full --augment

# Evaluate combined positioning quality (all 3 strategies work the same way)
python evaluate_pose.py \
    --mlo_config configs/wavelet_mlo.yaml \
    --cc_config  configs/wavelet_cc.yaml  \
    --threshold  10
```

## Preprocessing Pipeline

Every DICOM passes through 10 deterministic steps.  **Normalisation is
applied after cropping** so that 0–255 maps exclusively to breast tissue.

| Step | Operation | File |
|------|-----------|------|
| 1 | DICOM load + VOI LUT windowing | `src/data/dicom_loader.py` |
| 2 | MONOCHROME1 inversion | `src/preprocessing/pipeline.py` |
| 3 | Quick min-max→8-bit (preview) | `pipeline.py` |
| 4 | Otsu-based breast crop detection | `src/preprocessing/segmenter.py` |
| 5 | Keypoint-guided bbox expansion (80 px margin) | `pipeline.py` |
| 6 | Crop raw float32 data | `pipeline.py` |
| 7 | Normalise cropped region to 8-bit | `pipeline.py` |
| 8 | Resize: longest side → 640 px (aspect ratio preserved) | `pipeline.py` |
| 9 | **Enhancement strategy** (see below) | `src/preprocessing/strategies.py` |
| 10 | Laterality-aware black padding → 640×640 | `pipeline.py` |

## Enhancement Strategies

| Strategy key | Class | Description |
|-------------|-------|-------------|
| `baseline` | `BaselineStrategy` | No-op. Image returned unchanged. |
| `histeq` | `HistEqStrategy` | `cv2.equalizeHist` — global contrast stretch. |
| `wavelet` | `AdvancedWaveletStrategy` | NLM Denoise → Wavelet edge boost (db4, L2) → CLAHE. |

The `wavelet` strategy (Stage 1: NLM h=8, Stage 2: L1×1.6/L2×1.3 boost,
Stage 3: CLAHE clipLimit=2.5 8×8) consistently outperforms the others
on keypoint localisation accuracy for the VinDr-Mammo dataset.

## Data Augmentation

Horizontal flip augmentation doubles the dataset by creating mirrored
copies of every image, with properly transformed YOLO labels
(`new_x = 1.0 − old_x`).  Augmented files are suffixed `_flipped` and
are automatically excluded from test evaluation.

```bash
# Augment only the training split
python main.py --config configs/wavelet_mlo.yaml --mode augment --augment_splits train

# Augment train + val
python main.py --config configs/wavelet_mlo.yaml --mode augment --augment_splits train,val
```

## Evaluation

`evaluate_pose.py` is the **unified, config-driven evaluation script** that works
with all three strategies (baseline, histeq, wavelet) automatically.

### Single-view evaluation

```bash
# Baseline
python evaluate_pose.py --config configs/baseline_mlo.yaml

# Histogram Equalized
python evaluate_pose.py --config configs/histeq_mlo.yaml

# Advanced Wavelet (best)
python evaluate_pose.py --config configs/wavelet_mlo.yaml
```

Outputs → `evaluation_results/<strategy>/<view>/results.json`

### Combined positioning quality classification

```bash
# Wavelet strategy — single threshold
python evaluate_pose.py \
    --mlo_config configs/wavelet_mlo.yaml \
    --cc_config  configs/wavelet_cc.yaml  \
    --threshold  10

# With dual-threshold analysis (9/11 mm and 8/12 mm)
python evaluate_pose.py \
    --mlo_config configs/baseline_mlo.yaml \
    --cc_config  configs/baseline_cc.yaml  \
    --threshold 10 --dual_thresholds

# Skip DICOM visualisations (faster, useful without raw DICOMs)
python evaluate_pose.py \
    --mlo_config configs/wavelet_mlo.yaml \
    --cc_config  configs/wavelet_cc.yaml  \
    --skip_viz
```

Outputs → `evaluation_results/<strategy>/combined/`:

| File | Description |
|------|-------------|
| `evaluation_report.json` | Full metrics report |
| `summary_metrics.csv` | Human-readable summary table |
| `combined_results.json` | Per-pair predictions |
| `confusion_matrix.png` | Classification confusion matrix |
| `distance_correlation.png` | MLO PNL vs CC chest-wall scatter |

## YOLO Label Format

```
<class> <cx> <cy> <w> <h> <kp1_x> <kp1_y> <v1> [<kp2_x> <kp2_y> <v2>] ...
```

- All coordinates are **normalised to [0, 1]** relative to 640×640.
- Visibility: `2` = visible, `0` = not visible.
- Bounding box is computed from keypoints with 100 px padding (normalised).

| View | Keypoint order | `kpt_shape` |
|------|---------------|-------------|
| MLO | nipple, pectoral_top, pectoral_bottom | `[3, 3]` |
| CC | nipple | `[1, 3]` |

## Coordinate Transforms

Every processed image records its transformation parameters in `metadata.csv`.

| Parameter | Description |
|-----------|-------------|
| `crop_x1`, `crop_y1`, `crop_x2`, `crop_y2` | Breast crop in original DICOM pixels |
| `scale` | Resize factor (`640 / max(crop_h, crop_w)`) |
| `pad_left`, `pad_top`, `pad_right`, `pad_bottom` | Padding to reach 640×640 |
| `pixel_spacing` | mm/pixel from DICOM header |

### Forward transform (DICOM → 640×640)

```
final_x = (original_x − crop_x1) × scale + pad_left
final_y = (original_y − crop_y1) × scale + pad_top
```

### Inverse transform (640×640 → DICOM)

```
original_x = (predicted_x − pad_left) / scale + crop_x1
original_y = (predicted_y − pad_top)  / scale + crop_y1
```

### Pixel to millimetres

```
distance_mm = distance_pixels × pixel_spacing
```

## Dataset

**Source:** [VinDr-Mammo](https://physionet.org/content/vindr-mammo/1.0.0/)

| Property | Value |
|----------|-------|
| Image format | DICOM (12–16 bit grayscale) |
| Typical resolution | 3518 × 2800 pixels |
| Pixel spacing | 0.085 mm/pixel |
| Laterality | L / R encoded in `SeriesDescription` (e.g. `L-MLO`, `R-CC`) |
| Annotations | CSV — bounding boxes (Nipple) and line vertices (Pectoralis) |
| Splits | Train / Validation / Test (predefined in CSV) |
